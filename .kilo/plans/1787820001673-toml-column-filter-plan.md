# План: загрузка в PostgreSQL только колонок, описанных в TOML

## Цель

В БД должны попадать только колонки, явно описанные в секции `columns` TOML-файла
(`name` — исходное имя колонки в текстовом файле, `alias` — имя колонки в БД).
Все прочие колонки текстового файла отбрасываются и не загружаются.

Согласованные правила:
- Колонка файла отсутствует в TOML → не загружается (дроп), логируем список отброшенных.
- Колонка указана в TOML, но отсутствует в файле → пропускается, в лог пишется `warning`
  о неточности (`name` не найден в исходном файле).

## Контекст (текущий поток данных)

`app/server.py::_process_single_file`:
1. `report_loader.ReportHeaderParser().load_inventory_csv(path)` → `df` (колонки = заголовки файла).
2. `tables_settings.load_config(...)` → `Config` из TOML.
3. `tables_settings.apply_schema_to_dataset(df, report_settings, toml_file)` — сейчас только
   переименовывает `name`→`alias` и кастует типы, **но не отбрасывает лишние колонки**.
4. Строит `column_comments` из `ts["columns"]`.
5. `AsyncDatasetToPostgres(...)` загружает все колонки `df` (кроме `id/ID/Id`) + системную
   `date_download` (добавляется в `__init__`).

Точка фильтрации — шаг 3 (`apply_schema_to_dataset`), т.к. `date_download` добавляется
позже внутри загрузчика и не должна попадать под фильтр.

## Изменения

### 1. `app/settings/tables_settings.py` — `apply_schema_to_dataset`

Переработать функцию (строки 167–248):

- Построить маппинг настроенных колонок: для каждой записи `ts['columns']` с непустым `name`
  определить `db_name = alias if alias else name`.
- Переименовать существующие колонки файла `name` → `db_name` (как сейчас).
- Вычислить `kept` = список `db_name`, которые реально присутствуют в `df` после переименования
  (порядок — порядок колонок файла).
- `df = df.select(kept)` — физически отбросить колонки, не описанные в TOML.
- Логирование:
  - `logger.warning` для каждой настроенной колонки, чей `name` отсутствует в исходных колонках
    файла («неточность: колонка пропущена»).
  - `logger.info` одним сообщением со списком отброшенных колонок файла (не описанных в TOML).
- Приведение типов выполнять только для `kept`-колонок, с guard `if col_name in df.columns`
  (защита от `ColumnNotFoundError`).
- Вернуть отфильтрованный `df` (сигнатура не меняется).

### 2. `app/server.py` — фильтрация `column_comments`

После вызова `apply_schema_to_dataset` (строки 177–181) строить `column_comments` только для
колонок, оставшихся в `df`, чтобы `COMMENT ON COLUMN` не обращался к несуществующим колонкам:

```python
column_comments = {
    col["alias"]: col["comment"]
    for col in ts.get("columns", [])
    if col.get("alias") and col.get("comment") and col["alias"] in df.columns
}
```

### 3. `app/db/db_uploader.py` — защита `event_time` (robustness)

Если `event_time` ссылается на alias, которого нет среди загружаемых колонок, `delete_period`
упадёт на несуществующей колонке. Добавить в `delete_period` guard: если колонка `event_time`
не входит в `self.columns` → `logger.warning` и `return 0` (пропуск удаления периода).

## Не затрагивается / не меняется

- `date_download` — добавляется загрузчиком после фильтрации, попадает в БД как раньше.
- Исключение колонок `id/ID/Id` в загрузчике — без изменений.
- Автогенерация TOML (`from_dataset`) перечисляет все колонки файла → фильтр становится no-op.

## Риски / краевые случаи

- `event_time` должен присутствовать среди `kept`-колонок (см. п.3).
- Пустое `alias` → `db_name` берётся из `name` (fallback), чтобы колонка не терялась.
- Запись TOML с пустым `name` → игнорируется, `warning`.
- Порядок колонок `CREATE TABLE`/`COPY` определяется порядком колонок `df` (файла) — корректно,
  т.к. `copy_records_to_table` передаёт имена колонок явно.

## Валидация

- Добавить юнит-тест на `apply_schema_to_dataset`: df с лишними колонками → в результате только
  настроенные колонки с корректными alias; настроенная колонка, отсутствующая в df, пропущена.
- Прогнать существующие тесты: `python -m unittest` (см. `tests/test_period_validation.py`).
- Ручная проверка: обработать `.txt`, в логах — предупреждение о пропущенных колонках и список
  отброшенных колонок; в БД созданы только описанные в TOML колонки (+ `id`, `date_download`).
