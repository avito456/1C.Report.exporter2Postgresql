# План: универсальное разворачивание многоуровневых группировок (N-уровней)

## Проблема
В `app/parsers/report_loader.py` метод `_flatten_grouped` жёстко рассчитан на 2-строчную шапку группировки и 2 уровня иерархии. Файл `REPORT/ТестТоварыВПути.txt` имеет **3-строчную** шапку и **3 уровня**:
- stock_date (уровень 1)
- wh_name, wh_guid (уровень 2)
- item_name, item_guid, f(cost), item_type, price (детальные)

Текущая логика некорректно определяет зону измерений/мер и не умеет обновлять стек по многоуровневой вложенности.

## Цель
1. Доработать разворачивание группировок так, чтобы корректно обрабатывались **N-уровневые** ступенчатые группировки с **многострочной** шапкой.
2. Сохранить обратную совместимость: существующий тест `tests/test_grouped_report.py` (2 уровня) должен остаться зелёным.
3. Исправить **все места**, где парсится **группировочная шапка внутри табличного тела**. Текстовая шапка отчёта (период/отбор) — без изменений.
4. Уметь анализировать бóльшую глубину вложенности.

## Изученные места

- `load_body_to_dataframe()` — вызывает `_flatten_grouped()`. Критерий определения "сгруппированный" файл тоже завязан на 2-уровневом шаблоне. Возможно потребуется обобщить.
- `load_inventory_csv()`, `_parse_header_lines()`, `extract_period_from_header()`, `_read_file_with_retries()` — парсят **текстовую** шапку отчёта (до тела). Группировочная шапка внутри тела их не затрагивает. Менять не планируется.

### Тесты
- `tests/test_grouped_report.py` — 2-уровневый кейс. Обязательно сохранить поведение.

### Поиск
- `_flatten_grouped` встречается только в `report_loader.py`

**Основной фокус правок:** `app/parsers/report_loader.py::_flatten_grouped` (+ при необходимости мягко скорректировать критерий вызова).

## Структура ТестТоварыВПути.txt (ключевое понимание)

Табличное тело (после отделения BODY_PATTERN) начинается с 3 строк шапки группировки:

```
stock_date					stock_amount_way	stock_cost_way_rub        (h1)
wh_name	wh_guid					                                      (h2)
item_name	item_guid	f(cost)	item_type	price		                        (h3)
```

- Зона измерений (dimensions): колонки 0-5 (первые 6) формируют иерархию. Справа — меры.
- Меры: `stock_amount_way`, `stock_cost_way_rub` (правый блок, в h1 заполнены, в h2,h3 пусты)
- Уровни группировки сверху: 
  1. уровень 1: `stock_date`
  2. уровень 2: `wh_name`, `wh_guid`
- Листовые/детальные (нижний ряд шапки в зоне измерений): `item_name`, `item_guid`, `f(cost)`, `item_type`, `price`
- Подытоги: строки с заполненными только верхними уровнями + мерами. Детальная — строка, где **заполнены все leaf-детальные колонки**.

Ожидаемый плоский вид: колонки `stock_date, wh_name, wh_guid, item_name, item_guid, f(cost), item_type, price, stock_amount_way, stock_cost_way_rub`. Верхние уровни проставляются из стека по мере прохождения подытогов.

## Универсальный алгоритм

### 1) Блок группировочной шапки G
Взять `data_lines` (уже отфильтрованы пустые/не табличные, "Итого" отброшены до вызова). Найти **группировочную шапку** — первые k строк, формирующие многоуровневую ступенчатую шапку. 
Характерные признаки:
- Много пустот в правой "мерной" части
- В верхней строке есть названия мер справа
- В нижней строке есть имена детальных измерений слева

Достаточно взять `data_lines[0 : m]` где m — число строк до первой строки, которая выглядит как **детальная** относительно этой шапки (но в шапке их нет). На практике для типичных выгрузок 1С группировочная шапка — 2..4 строки.

### 2) Построить матрицу H
`H[i][j] = data_lines[i].split('\t')[j].strip()` для `i < len(G)`, `j < width`.

### 3) Определить зону мер `measure_start_col`
Найти первый столбец j такой, что:
- `H[0][j] != ''` (верхняя строка шапки содержит название меры)
- и в большинстве нижних строк шапки `H[1..m-1][j] == ''` (в ступенчатой шапке меры дублируются только сверху)

Либо как альтернатива — правый блок, где верхний ряд заполнен названиями показателей.

### 4) Зона измерений
`dim_cols = 0 .. measure_start_col-1`. Именно в ней выстраивается иерархия уровней.

### 5) Выделить уровни группировки + detail_cols
Для ступенчатой структуры:
- **detail_cols** (листовые) — имена из **нижней** строки группировочной шапки в зоне измерений: `H[m-1][j]` для `j < measure_start_col`. Берём только те, что непустые? Обычно да. Именно по заполненности **всех** этих detail_cols отличаем детальную строку от подытога.
- **group levels** (уровни сверху) — определяем по строкам сверху вниз. Уровень r соответствует колонкам j в зоне измерений, для которых "ячейка уровня" впервые проявляется на строке r. У ступенчатой группировки: `H[r][j] != ''` при этом выше по вертикали в этой "ступеньке" пусто. Также можно трассировать, какие колонки относятся к какому уровню иерархии.

Более практичный подход для 1С-ступенчатой шапки:
- detail block — последняя строка шапки G: все непустые `H[m-1][j]`, `j < measure_start_col`.
- level 0 (верхний) — колонки j где `H[0][j] != ''` и (m == 1 или `H[1][j] == ''`) в типичном 2-уровневом? Или точнее: для каждого уровня k сверху, колонка j принадлежит уровню k, если `H[k][j] != ''` и `k == 0 or H[k-1][j] == ''`? Нужна аккуратная эвристика, сохраняющая совместимость с текущим тестом.

Альтернативный надёжный способ:
1. В зоне измерений выделить **detail_cols** = список `(j, name)` из нижнего ряда `m-1`: где `name != ''`. Пусть `detail_j_set = {j for j,_ in detail_cols}`.
2. **Групповые уровни** — это последовательность уровней сверху вниз. Для каждого уровня `lvl` (0-based сверху) собираем список колонок j в `0..measure_start_col-1`, которые "принадлежат" этому уровню группировки, но **не** являются detail. Т.е. `H[lvl][j] != ''` и колонка j не входит в detail-блок нижней строки? У ступенчатой шапки: над detail-ячейками выше стоят группирующие заголовки.
3. При этом для строки тела: **детальная**, если **каждая** колонка из `detail_cols` имеет непустое значение в `dim_cells`.

### 6) Критерий "это сгруппированный файл"
Новый алгоритм должен срабатывать, если:
- `len(G) >= 2` (многострочная шапка группировки)
- `measure_start_col > 0` и есть хотя бы одно название меры в `H[0][measure_start_col:]`
- Есть **минимум 2 "блока"**: группирующие уровни + detail-блок
- Структура ступенчатая: в шапке много пустот

Важно не срабатывать на по-настоящему плоский файл (где только 1 строка заголовков). Текущий код в `load_body_to_dataframe` вызывает `_flatten_grouped` только если "похоже на сгруппированный". При `None` — читает как CSV с `has_header=True`.

Нам нужно сохранить поведение `test_flat_is_unchanged`: плоский файл с 1-строчной шапкой не должен "сплющиваться" через новый алгоритм. Значит если группировочная шапка **не определилась** как ступенчатая с уровнями — вернуть `None`.

### 7) Обход тела и раскладка
Имеем `stack` по уровням: для каждого group-уровня храним последнее значение, когда встретили подытог этого уровня.

Для каждой строки `s` в `data_lines[m:]`:
- разбить в `cells`, добить до `width` пустыми
- `dim_cells = cells[0:measure_start_col]`
- `meas_cells = cells[measure_start_col:]`

Проверка детальности:
```python
is_detail = all(dim_cells[j].strip() != '' for j,_ in detail_cols)
```

Если **не детальная** (подытог):
- найти "глубину" подытога: как много уровней группировки заполнены сверху? Обычно последняя непустая колонка в `dim_cells` указывает на закрываемый уровень. Обновить `stack` для уровней 0..k: проставить значения из `dim_cells` тех колонок, что относятся к этим уровням. Более глубокие уровни можно очистить.
- **не добавлять** строку в результат.

Если **детальная**:
- собрать список значений в порядке итоговых колонок:
  1. для каждого group-уровня в порядке: для каждой колонки уровня взять `stack.get((lvl, j), '')` или просто значение из стека уровня
  2. для каждой `detail_cols`: взять `dim_cells[j].strip()`
  3. для каждой меры: взять `meas_cells[...]` (как есть)
- добавить в `rows`

### 8) Формирование DataFrame
